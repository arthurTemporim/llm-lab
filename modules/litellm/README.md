# LiteLLM

OpenAI-compatible gateway in front of Ollama, LocalAI and cloud providers, with keys, budgets, routing and metrics.

## Overview

| | |
|---|---|
| Documentation | [LiteLLM](https://docs.litellm.ai/) |
| Image | `ghcr.io/berriai/litellm:v1.104.1`, `prom/prometheus:v3.15.0` |
| Container(s) | `litellm`, `litellm-init` (one-shot), `litellm-prometheus` |
| GPU | Not used |
| Make target | `make litellm` |

## What it is used for

* One API and one key for many model backends.
* Virtual keys, budgets, routing and an admin UI.
* Prometheus metrics, and optional traces to Langfuse.

## Access

| What | Host (browser, CLI) | Inside the `lang` network |
|---|---|---|
| API and admin UI | http://localhost:4000 (UI at `/ui`) | http://litellm:4000 |
| Prometheus | http://localhost:9090 | http://litellm-prometheus:9090 |

Admin UI login: `litellm` / `litellm123` (`UI_USERNAME`, `UI_PASSWORD`). API calls use `LITELLM_MASTER_KEY` as Bearer token.

## Quick start

```sh
make litellm
make litellm-logs
```

Check that it works:

```sh
curl http://localhost:4000/health/liveliness
```

Every model pulled in Ollama is registered at startup (see [Models](#models)). List them:

```sh
curl -H "Authorization: Bearer $LITELLM_MASTER_KEY" http://localhost:4000/v1/models
```

## Models

`make litellm` first runs `litellm-init`, which writes LiteLLM's `config.yaml` and exits, then starts `litellm` with that file:

1. `generate_config.py` lists the Ollama models (`/api/tags`) and reads each one's capabilities and context length (`/api/show`).
2. Chat models get `ollama_chat/<name>`, embedding models `ollama/<name>`, with the per-mode `defaults` of `models.yaml`. `model_info` (context, output tokens, vector size, vision/tools/reasoning) is filled from Ollama.
3. The entry for that model in `models.yaml` `models:` is merged on top. Use it for per-model settings (`keep_alive`, `num_ctx`, `max_tokens`), for decision models (`model_info: { mode: decisions }`, which uses the `typesafe/` provider), or `enabled: false` to leave a model out.
4. `extra_models` (LocalAI, vLLM, cloud) and `litellm_settings` / `general_settings` / `router_settings` are copied as-is.

After pulling a new model or editing `models.yaml`, run `make litellm` again. A plain container restart reuses the last config. If Ollama is not reachable within `OLLAMA_WAIT_SECONDS`, the last generated config is kept.

```sh
docker logs litellm-init                     # what was added, skipped or missing
docker exec litellm cat /config/config.yaml  # the generated config
```

## Configuration

Edit `modules/litellm/.env` (created by `make create-envs` from `example.env`), then `make litellm` to apply.

| Variable | Default | Description |
|---|---|---|
| `LITELLM_PORT` | `4000` | Host port of the gateway |
| `PROMETHEUS_PORT` | `9090` | Host port of Prometheus |
| `DATABASE_URL` | `postgresql://<POSTGRES_USER>:<POSTGRES_PASSWORD>@postgres:5432/litellm` | Shared Postgres |
| `STORE_MODEL_IN_DB` | `False` | `True` also loads models added in the UI; a model in both places gets two deployments |
| `OLLAMA_API_BASE` | `http://ollama:11434` | Ollama used for discovery and as `api_base` of the generated models |
| `OLLAMA_WAIT_SECONDS` | `60` | How long `litellm-init` waits for Ollama |
| `LITELLM_MASTER_KEY` | `sk-CHANGE_ME` | **Secret.** Admin API key, must start with `sk-`. Generated by `make create-envs` |
| `LITELLM_SALT_KEY` | `sk-CHANGE_ME` | **Secret.** Encrypts stored provider keys. **Never change after first use** |
| `UI_USERNAME` / `UI_PASSWORD` | `litellm` / `litellm123` | Admin UI login. Change the password |

Model settings are in `models.yaml` (see [Models](#models)). Prometheus scrape config is `prometheus.yml`.

Langfuse tracing: add `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and `LANGFUSE_HOST=http://langfuse-web:3000` to `.env`, and `litellm_settings: { success_callback: ["langfuse"] }` to `models.yaml`.

## Connections

| Direction | Module | How |
|---|---|---|
| Depends on | `common-services` | Postgres database `litellm` |
| Depends on | `ollama` | Model discovery at start (`litellm-init`) and backend |
| Depends on | `localai` | Optional, runtime: model backend (`extra_models`) |
| Depends on | `langfuse` | Optional, runtime: trace callback |
| Used by | `langflow` | Optional, `http://litellm:4000` |
| Used by | `openwebui` | Optional OpenAI connection (`http://litellm:4000/v1`) |

## Storage

| Data | Where | Survives `down` |
|---|---|---|
| Keys, spend | Postgres database `litellm` | yes |
| Generated `config.yaml` | `litellm_config` named volume | yes |
| Prometheus data (15 days) | `prometheus_data` named volume | yes |

## Operations

```sh
make litellm-down     # stop, keep data
```

Upgrade: change the image tag, then `docker compose pull && docker compose up -d` in `modules/litellm/`.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `401` | Send `Authorization: Bearer <LITELLM_MASTER_KEY or a virtual key>` |
| `database "litellm" does not exist` | `make databases` |
| Provider keys unreadable | `LITELLM_SALT_KEY` was changed; restore it |
| Port 9090 already in use | Change `PROMETHEUS_PORT` |
| A pulled model is missing | Run `make litellm` again; check `docker logs litellm-init` |
| `litellm` does not start, `litellm-init` exited 1 | Syntax error in `models.yaml`; see `docker logs litellm-init` |
| Every model listed twice | `STORE_MODEL_IN_DB=True` with the same models in the DB: set it to `False` or delete the DB copies |

## Notes

* Defaults are for local development only.
