# Modules

What each module in `modules/` is for, and the rules every module follows. Variables are in [CONFIGURATIONS.md](CONFIGURATIONS.md); how modules connect is in [ARCHITECTURE.md](ARCHITECTURE.md). Ports, versions and credentials are defined in each module's `docker-compose.yml` and `example.env`.

## Module contract

```text
modules/<name>/
├── docker-compose.yml   # required: joins the external "lang" network, pins image versions
├── docker-compose.gpu.yml # optional: NVIDIA override, base file must run on CPU
├── example.env          # safe defaults with comments, every host port as a variable
├── .env                 # generated by `make create-envs`, git-ignored
├── Dockerfile           # optional: only when extending an upstream image
├── README.md            # required: follows MODULE_README_TEMPLATE.md
└── <assets>             # optional: configs, flows, notebooks
```

Rules:

1. Use a `container_name` equal to the service's DNS name on the network.
2. Reuse `common-services`; don't bundle your own Postgres, Redis or S3.
3. Add a `healthcheck` when the image provides one.
4. Publish ports as `"${NAME_PORT:-default}:container"` with the variable in `example.env`. Pick a free host port and bind admin-only ones to `127.0.0.1`.
5. Load the config with `env_file: .env`; use `${VAR}` interpolation only for ports and derived values.
6. Use `restart: unless-stopped` and pin image tags.
7. Register the module in the `Makefile` (`MODULES` list, nothing else).

## Modules

### common-services

The foundation. Creates the shared network and runs Postgres (with pgvector), Redis and MinIO. Always start it first. `make common-services` creates the `langflow`, `langfuse` and `litellm` databases (with `vector`) on any volume. Redis runs with `noeviction` because Langfuse requires it.

### ollama

Pulls, runs and serves open-weight LLMs and embedding models, with its own API and an OpenAI-compatible one. Models are stored in a volume. Pull models with `scripts/ollama_pull_model.sh` (edit its list) or `docker exec ollama ollama pull <model>`. Uses the GPU when available.

### localai

OpenAI-compatible server for LLMs, embeddings, images and audio. The all-in-one image ships preconfigured models and downloads them on first start. Requires an API key, generated into its `.env`. Uses the GPU when available, the CPU image otherwise.

### openwebui

ChatGPT-style web UI with RAG, web search, code execution and image generation. Preconfigured for Ollama; add other OpenAI-compatible connections (LocalAI, LiteLLM) in the admin settings. The first sign-up becomes admin. Uses the GPU for local embeddings when available.

### langflow

Low-code visual builder for chains, agents and RAG. Built from a custom Dockerfile that adds extra bundles. Flows are stored in Postgres. `langflow.json` has example flows to import. In components use the container names of Ollama or LiteLLM, not `localhost`.

### notebooks

Jupyter playground with LangChain and the Ollama integration. Notebooks are bind-mounted so work stays on the host. Add Python packages in `requirements.txt` and rebuild. Includes a basic chain notebook and a RAG example. Runs without a token, so keep it local.

### litellm

OpenAI-compatible gateway in front of Ollama, LocalAI and cloud providers, with keys, budgets, routing, an admin UI and Prometheus metrics. Uses the `litellm` database in Postgres. Models can be managed in the UI or through a mounted `config.yaml`. Can send traces to Langfuse.

### langfuse

LLM observability: traces, sessions, prompts, evals and datasets. Runs a web app, a worker and ClickHouse, and uses Postgres, Redis and MinIO from `common-services`. Set its secrets in `.env` before starting. `make langfuse` also checks that the MinIO credentials match. See `modules/langfuse/README.md` for the full reference.

## Adding a module

1. Create `modules/<name>/` following the contract above.
2. Write `docker-compose.yml` with the external network and a pinned image.
3. Write `example.env` with every variable commented.
   Write `README.md` from [MODULE_README_TEMPLATE.md](MODULE_README_TEMPLATE.md).
4. Add the name to `MODULES` in the `Makefile`. Targets `<name>`, `<name>-logs`, `<name>-down`, `build`, `down` and `create-envs` then work. New databases go in `POSTGRES_DATABASES` (`common-services/example.env`).
5. Update the README module table and these docs (`MODULES`, `CONFIGURATIONS`, and `ARCHITECTURE` if it adds a dependency or flow).
6. Validate with `docker compose -f modules/<name>/docker-compose.yml config -q`, then start it for real.
